% System Context — arc42 §3 "Context and Scope".
% Converted from context_diagram.d2 when the project moved to TikZ/tectonic.
%
% Notation: a UML use-case-style context sketch — the actor is a UML stick
% figure, tsam and its neighbours are «system» components, and the arrows are
% labelled with what actually crosses each boundary. arc42 §3 prescribes no
% notation, only that the diagram show the system in its environment and name
% every external interface.
%
% The point of this diagram is the SCOPE LINE: tsam neither reads files nor
% calls any downstream framework. Both of those are the user's job, which is why
% the modeler — not tsam — owns the arrow into the downstream frameworks.
%
% Print target: DIN A4 portrait, 165 mm printable width, ~235 mm usable height.
% Font sizes are real points (\small = 9 pt, \footnotesize = 8 pt at a 10 pt
% base), so the print budget holds by construction.
%
% Guillemets MUST be written as \guillemotleft / \guillemotright — literal UTF-8
% « » lands on the wrong glyph slot under T1 encoding.
%
% Regenerate:
%   tectonic context_diagram.tex
%   pdftocairo -svg context_diagram.pdf context_diagram.svg

  {\textbf{Scope.} tsam does not read files, write files, or call any downstream
   framework --- all of that is the user's responsibility, which is why the arrow
   into the downstream frameworks starts at the modeler and not at tsam. The only
   optional external dependency is a MILP solver, required when
   \texttt{ClusterConfig(method="kmedoids")} runs exactly; every other clustering
   method runs without one.};
