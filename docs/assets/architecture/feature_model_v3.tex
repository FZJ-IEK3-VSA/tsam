% Feature Model of the tsam aggregation configuration — VERSION 3.
%
% v1 = feature_model.tex        (phase tags, no owners)
% v2 = feature_model_v2.tex     (phase tags AND owners — mixed two concerns)
% v3 = this file                (owners only, one owner per column)
%
% Notation: FODA feature diagram (Kang et al., CMU/SEI-90-TR-21, 1990), the
% software-product-line notation for describing the space of valid
% configurations:
%   filled circle on an edge   = MANDATORY feature
%   open circle on an edge     = OPTIONAL feature
%   unfilled arc across a fan  = ALTERNATIVE group (choose EXACTLY ONE)
%   filled arc across a fan    = OR group (choose ONE OR MORE)
%   dashed arrow               = cross-tree constraint (requires)
%
% ── WHAT V3 CHANGES, AND WHY ──────────────────────────────────────────────
%  1. THE PHASE TAGS ARE GONE. A feature model describes which configurations
%     are legal; WHEN a feature takes effect is a runtime concern and belongs to
%     the architecture figure, which already shows all four phases with their
%     stage lists. The tags were also not even true: `weights` is applied in
%     Phase 1 and undone in Phase 3, so no single phase labels it. Column order
%     still follows the pipeline, which carries the sequence implicitly without
%     the diagram asserting temporal semantics it has no notation for.
%  2. ONE OWNER PER COLUMN. v2 tagged the Weighting group `ClusterConfig` and
%     then had to tag one leaf `aggregate()`, because `weights` is a keyword
%     argument while the scaling flags are ClusterConfig fields. A column that
%     mixes owners defeats the point of the tag, so the aggregate() keywords now
%     have their own column and every column names exactly one object.
%  3. MinMaxMean IS EXPANDED, like Distribution. Both are classes a caller
%     constructs, so both get their parameters drawn. max_columns / min_columns
%     form an OR group: MinMaxMean with neither populated returns plain mean
%     (see issue #490), so at least one is required for the feature to do
%     anything.
%
% ── OWNERSHIP, VERIFIED AGAINST THE CODE ──────────────────────────────────
% src/tsam/api.py:25-38 and src/tsam/config.py:
%   aggregate()     weights, preserve_column_means, rescale_exclude_columns
%   ClusterConfig   method, representation, scale_by_column_means,
%                   use_duration_curves, include_period_sums
%   ExtremeConfig   method
%   SegmentConfig   n_segments, representation
%   Distribution    scope, preserve_minmax, concurrency  (a value of
%                   ClusterConfig.representation / SegmentConfig.representation)
%   MinMaxMean      max_columns, min_columns  (likewise)
%
% ── WHY SOME GROUPS HAVE NO ARC ───────────────────────────────────────────
% An arc means the children form a group — pick exactly one, or pick one or
% more. The aggregate() keywords, the ClusterConfig flags and Segmentation's
% two fields are not groups: each is independently settable, so each edge
% carries its own marker instead. v1/v2 drew the weighting options as an OR
% group, which was wrong — nothing forces you to set any of them.
%
% ── PALETTE: TWO COLOURS, SHARED WITH THE ARCHITECTURE OVERVIEW ───────────
% Jülich blue and one grey, plus a tint of each, all of it declared once in
% palette.tex and \input by both manuscript figures. See that file for the
% reviewer request behind it.
%
% Here the two colours carry MANDATORY versus OPTIONAL: a blue column is one
% you always configure, a grey column one you can leave alone, and the colour
% runs down the whole subtree so an optional branch reads as optional all the
% way to its leaves. This is REINFORCEMENT, not the notation — FODA already
% says it with the filled/open circle on each edge, so the figure survives
% being printed in greyscale.
%
% What this revision spent to get there:
%   * amber and its warm tint became fzjgrey and fzjgreytint, unchanged in
%     every other respect (the optional group boxes keep their dashed border);
%   * the legend's two group arcs, drawn in black because an arc is an arc
%     regardless of its column, became fzjblue — the palette's neutral;
%   * fzjdark (a near-black blue, used for text only) collapsed into fzjblue.
%
% ── PRINT TARGET ──────────────────────────────────────────────────────────
% Text column 165.1 x 228.6 mm, figures at full width: ASPECT h/w <= 1.24 and
% WIDTH <= ~165 mm. Dropping the phase line returns the group boxes to 11 mm
% and the leaf pitch to 10 mm, which is what pays for MinMaxMean's expansion.
%
% ── MEASURED WIDTHS (\settowidth, read out of the PDF) ────────────────────
% Leaf boxes are 21 mm wide with 18.5 mm of text width; group boxes 24.5 /
% 21.5 mm. At \scriptsize:
%   representation 17.43   column_means 18.56   max_columns 17.23
%   MinMaxMean     17.01   Distribution 14.97   hierarchical 14.16
%   n_segments     14.64   new_cluster  15.04   independent  14.96
%   Keyword options 20.72 (breaks at the space)
% At \tiny: ClusterConfig \ttfamily 12.14, aggregate() \ttfamily 10.27,
%   rescale_exclude_ 18.31.
% All inside their boxes. `representation` was suspected of overflowing and
% does not — 17.43 < 18.5.
%
% ── LAYOUT GRID (millimetres, y negative downwards) ───────────────────────
% BAND 1 — six columns, pitch 27, boxes 24.5 mm:
%   c1 = 17 Keyword options  c2 = 44 Grouping       c3 = 71 Representation
%   c4 = 98 Clustering input c5 = 125 Extreme       c6 = 152 Segmentation
%   root (84.5,-8) 44x9   bar -18   markers -20.7   groups -24..-35
%   leaf bus ci-15, elbow -40 -> -38, stub ci-15 -> ci-10.5
%   leaves 21 mm (ci +/- 10.5), rows -46 -56 -66 -76 -86 -96
% BAND 2 — two expansions side by side, so MinMaxMean costs no extra height:
%   Distribution root (50,-110) 44x9;  MinMaxMean root (136,-110) 44x9
%   Distribution sub-columns pitch 32: 18, 50, 82; boxes and leaves 24 mm;
%     sub-bus ci-16, elbow -140, leaves rows -147 -156 -165 -174 -183
%   MinMaxMean bus x 110, leaves 40 mm at (136,-125) and (136,-134)
%   Lanes: Distribution connector x 86 (y -76..-104), MinMaxMean connector
%     x 89 (y -86..-98) then y -98 eastwards — starts right of 86, so the two
%     never cross. Constraint lane x 32: 2 mm from scope's leaves (end 30) and
%     2 mm from concurrency's bus (34).
%
% ── TRAPS ─────────────────────────────────────────────────────────────────
%   * A TikZ node CLIPS NOTHING and LaTeX will not break at `\_`.
%   * A TikZ STYLE cannot be applied to part of a node's text; the owner tag
%     uses a \newcommand DECLARATION.
%   * NEVER sed this file — a `s/\\wd/.../` pattern once rewrote every bare
%     "wd", turning \newcommand into \newcommamywd.
%
% Regenerate — from THIS directory, because \input{palette} resolves against
% the working directory:
%   tectonic feature_model_v3.tex
%   pdftocairo -svg feature_model_v3.pdf feature_model_v3.svg
%   pdftocairo -png -r 600 -singlefile feature_model_v3.pdf feature_model_v3
