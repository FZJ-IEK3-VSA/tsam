% Feature Model of the tsam aggregation configuration — VERSION 3.
%
% v1 = feature_model.tex        (phase tags, no owners)
% v2 = feature_model_v2.tex     (phase tags AND owners — mixed two concerns)
% v3 = this file                (owners only, one owner per column)
%
% Notation: FODA feature diagram (Kang et al., CMU/SEI-90-TR-21, 1990), the
% software-product-line notation for describing the space of valid
% configurations:
%   filled circle on an edge   = MANDATORY feature
%   open circle on an edge     = OPTIONAL feature
%   unfilled arc across a fan  = ALTERNATIVE group (choose EXACTLY ONE)
%   filled arc across a fan    = OR group (choose ONE OR MORE)
%   dashed arrow               = cross-tree constraint (requires)
%
% ── FONT SIZES ARE SET HERE, NOT INHERITED FROM THE CLASS ─────────────────
% Reader request: 11 pt for the ordinary type and 8 pt for the smallest. Both
% are met, and the sizes are the same ones the architecture overview declares,
% so the two manuscript figures cannot drift apart.
%
%              class 10pt      here        printed (x 165.1/163.7)
%   \small       9 pt        11 pt        11.09 pt
%   \scriptsize  7 pt         8 pt         8.07 pt
%   \tiny        5 pt         8 pt         8.07 pt
%
% \scriptsize and \tiny are BOTH 8 pt, which collapses what used to be two
% levels into one. That is not laziness: 8 pt is the floor the request sets and
% 8 pt is simultaneously the CEILING this figure's grid allows for its leaves
% (below), so there is no room between them. What used to separate the owner
% tag from the leaf text was size; now it is the monospace face and the tag's
% position under the group name, which is enough and survives greyscale.
%
% ── WHY 8 PT IS ALSO THE CEILING ──────────────────────────────────────────
% The printed size of a glyph is set by the DRAWING'S WIDTH — the figure is
% placed at the full text width whatever its own width, so
%
%       printed pt = source pt x 165.1 / (drawing width in mm)
%
% and scaling the drawing up buys nothing. Band 1 is a six-column grid whose
% width is an identity:
%
%       width = 5p + 2h + arc + clearance,   p = 2h + arc + 2 x clearance
%
% with h the half-width of a leaf box. At 165 mm and six columns that pins
% h <= 11.25 mm, i.e. 20 mm of text width per leaf, FULL STOP — there is no
% arrangement of these six groups that gives a leaf more room. The widest leaf
% token then decides the font:
%
%       column_means   19.85 mm at 8 pt   <- binds every band-1 column
%       ClusterConfig  19.42 mm at 8 pt   <- the owner tag, \ttfamily, in the
%                                            group box's identical 20 mm
%
% Both land inside 20 mm, `column_means` with 0.15 mm to spare and the owner
% tag with 0.58 mm. At 8.5 pt `column_means` needs 21.1 mm, hence a 27.8 mm
% pitch, hence a 168 mm drawing — which the page would scale back DOWN by more
% than the half point won.
%
% ── WHAT PAID FOR IT ──────────────────────────────────────────────────────
%   * the group boxes went 24.5 -> 22.5 mm. They were the widest thing in each
%     column and set the drawing's right edge while holding at most a
%     ten-character bold word. Now the LEAF sets the edge.
%   * the arc x-radius went 3 -> 2.5 mm and the two clearances 1.5 -> 1.0 mm,
%     which is 1.5 mm of leaf width per column while the pitch stays at 27.
%     The arcs read the same: what makes them visible is their HEIGHT.
%   * band 2's leaves went 8 -> 6.5 mm tall on an 8 mm pitch. All eleven are
%     single-line, so the 8 mm was air.
%   * band 2's sub-group boxes went 11 -> 9 mm, for the same reason.
% Net: the drawing went from 164.7 x 203.6 mm to 163.7 x 200.6 mm — narrower
% AND shorter — so the type gained on both terms of the quotient at once.
%
% ── THE ONE LEAF THAT NEEDED A THIRD LINE ─────────────────────────────────
% `rescale_exclude_columns` is 23 characters. It used to be the one leaf set a
% size smaller; with \tiny and \scriptsize both at 8 pt that escape is gone, so
% it is broken at its underscores into `rescale_` / `exclude_` / `columns`
% (13.2 / 13.2 / 11.6 mm). Three lines need 12.1 mm of box against the row's
% 8.75 mm, and `minimum height` is a MINIMUM — the node grows and would have
% closed the 1.75 mm gap to the row above to 0.075 mm.
%
% It is therefore the one leaf placed with `anchor=north`, at the row's TOP
% edge (-63.125) rather than its centre. Its top lines up with every other
% row-3 leaf and it grows DOWNWARDS, into column 1's empty space — c1 has only
% three leaves and nothing below them. Raising the whole band's pitch to 11.5
% would have cost 5 mm of height for one leaf.
%
% ── WHAT V3 CHANGES FROM V2, AND WHY ──────────────────────────────────────
%  1. THE PHASE TAGS ARE GONE. A feature model describes which configurations
%     are legal; WHEN a feature takes effect is a runtime concern and belongs to
%     the architecture figure, which already shows all four phases with their
%     stage lists. The tags were also not even true: `weights` is applied in
%     Phase 1 and undone in Phase 3, so no single phase labels it. Column order
%     still follows the pipeline, which carries the sequence implicitly without
%     the diagram asserting temporal semantics it has no notation for.
%  2. ONE OWNER PER COLUMN. v2 tagged the Weighting group `ClusterConfig` and
%     then had to tag one leaf `aggregate()`, because `weights` is a keyword
%     argument while the scaling flags are ClusterConfig fields. A column that
%     mixes owners defeats the point of the tag, so the aggregate() keywords now
%     have their own column and every column names exactly one object.
%  3. MinMaxMean IS EXPANDED, like Distribution. Both are classes a caller
%     constructs, so both get their parameters drawn. max_columns / min_columns
%     form an OR group: MinMaxMean with neither populated returns plain mean
%     (see issue #490), so at least one is required for the feature to do
%     anything.
%
% ── OWNERSHIP, VERIFIED AGAINST THE CODE ──────────────────────────────────
% src/tsam/api.py:25-38 and src/tsam/config.py:
%   aggregate()     weights, preserve_column_means, rescale_exclude_columns
%   ClusterConfig   method, representation, scale_by_column_means,
%                   use_duration_curves, include_period_sums
%   ExtremeConfig   method
%   SegmentConfig   n_segments, representation
%   Distribution    scope, preserve_minmax, concurrency  (a value of
%                   ClusterConfig.representation / SegmentConfig.representation)
%   MinMaxMean      max_columns, min_columns  (likewise)
%
% ── WHY SOME GROUPS HAVE NO ARC ───────────────────────────────────────────
% An arc means the children form a group — pick exactly one, or pick one or
% more. The aggregate() keywords, the ClusterConfig flags and Segmentation's
% two fields are not groups: each is independently settable, so each edge
% carries its own marker instead. v1/v2 drew the weighting options as an OR
% group, which was wrong — nothing forces you to set any of them.
%
% ── PALETTE: TWO COLOURS, SHARED WITH THE ARCHITECTURE OVERVIEW ───────────
% Jülich blue and one grey, plus a tint of each, all of it declared once in
% palette.tex and \input by both manuscript figures. See that file for the
% reviewer request behind it.
%
% Here the two colours carry MANDATORY versus OPTIONAL: a blue column is one
% you always configure, a grey column one you can leave alone, and the colour
% runs down the whole subtree so an optional branch reads as optional all the
% way to its leaves. This is REINFORCEMENT, not the notation — FODA already
% says it with the filled/open circle on each edge, so the figure survives
% being printed in greyscale.
%
% ── PRINT TARGET ──────────────────────────────────────────────────────────
% Text column 165.1 x 228.6 mm, figures at full width: ASPECT h/w <= 1.24 and
% WIDTH <= ~165 mm. This file is 163.7 x 200.6 mm, aspect 1.225 — inside on
% both counts, with ~2.4 mm of height in hand. The aspect is what breaks
% first, so anything added has to take a row away.
%
% ── MEASURED WIDTHS (_measure.tex: \settowidth, then TYPESET, because
%    tectonic swallows \typeout) ────────────────────────────────────────────
% Band-1 leaf boxes are 22.5 mm wide with 20 mm of text width; group boxes the
% same. At \scriptsize = 8 pt:
%   column_means 19.85 <- binds   representation 18.53   MinMaxMean   18.25
%   use_duration 17.53            period_sums    17.04   new_cluster  16.03
%   Distribution 15.91            n_segments     15.63   hierarchical 15.03
%   contiguous   13.88            preserve_      12.88   averaging    12.37
%   kmedoids     12.22            include_       11.53   _curves      10.39
%   scale_by     11.55
% At \scriptsize = 8 pt bold, group names:
%   Clustering 17.8   Represen- 15.06   Grouping 14.27   Extreme 12.86
%   Segmen-    12.72  Keyword   12.5    periods  11.06
% At \tiny = 8 pt \ttfamily (monospace, 1.494 mm/char), owner tags:
%   ClusterConfig / SegmentConfig / ExtremeConfig  19.42 (13 chars) <- binds
%   aggregate()                                    16.43 (11 chars)
%   rescale_ / exclude_ / columns                  13.2 / 13.2 / 11.6
% Band 2 (24 mm sub-boxes, 21 mm text; 40 mm wide leaves, 37 mm text):
%   concurrency 18.30 bold   independent 15.93   assignment 14.39
% Legend, longest run ends at x 150.4; the drawing ends at 163.4.
%
% ── LAYOUT GRID (millimetres, y negative downwards) ───────────────────────
% BAND 1 — six columns, pitch 27, leaf and group boxes both 22.5 mm:
%   c1 = 17 Keyword options  c2 = 44 Grouping       c3 = 71 Representation
%   c4 = 98 Clustering input c5 = 125 Extreme       c6 = 152 Segmentation
%   root (84.5,-8) 44x9   bar -17.5   markers -20.2   groups -23.5..-35.5
%   leaf bus ci-14.75, elbow -38.5, stub ci-14.75 -> ci-11.25
%   leaves 22.5 mm (ci +/- 11.25), 8.75 mm tall,
%     rows -46.5 -57 -67.5 -78 -88.5 -99 (pitch 10.5)
%   arcs: x radius 2.5 at (ci-11.25, first row), y radius = half the row span,
%     so 26.25 (c2, 6 leaves), 21 (c3, 5), 10.5 (c5, 3). c1, c4 and c6 have no
%     arc — see WHY SOME GROUPS HAVE NO ARC.
%   The 2.5 mm bulge reaches ci-13.75 and the bus is at ci-14.75: 1 mm of
%   clearance, and 1 mm again between one column's leaf (ci+11.25) and the
%   next column's bus (ci+12.25).
% BAND 2 — two expansions side by side, so MinMaxMean costs no extra height:
%   Distribution root (50,-115) 44x9;  MinMaxMean root (136,-115) 44x9
%   Distribution sub-columns pitch 32: 18, 50, 82; boxes and leaves 24 mm;
%     sub-bus ci-16, elbow -142.5, leaves 6.5 mm tall,
%     rows -149 -157 -165 -173 -181 (pitch 8)
%   MinMaxMean bus x 110, leaves 40 mm at (136,-128) and (136,-137) — a 9 mm
%     pitch, not 8, so its filled arc stays legible; see the note there
%   Lanes: Distribution connector x 85 (y -78..-108) then west; MinMaxMean
%     connector x 88 (y -88.5..-102) then east. 85 < 88, so the two never
%     cross, and both clear c4's leaves (86.75..109.25) in y.
%     Constraint lane x 32: 2 mm from scope's leaves (end 30) and 2 mm from
%     concurrency's bus (34).
% LEGEND rows -191 and -199.
%
% ── TRAPS ─────────────────────────────────────────────────────────────────
%   * A TikZ node CLIPS NOTHING and LaTeX will not break at `\_`.
%   * `minimum height` is a MINIMUM — see THE ONE LEAF THAT NEEDED A THIRD
%     LINE for what that costs and how it is paid.
%   * A TikZ STYLE cannot be applied to part of a node's text; the owner tag
%     uses a \newcommand DECLARATION.
%   * NEVER sed this file — a `s/\\wd/.../` pattern once rewrote every bare
%     "wd", turning \newcommand into \newcommamywd.
%

%   tectonic feature_model_v3.tex
%   pdftocairo -svg feature_model_v3.pdf feature_model_v3.svg
