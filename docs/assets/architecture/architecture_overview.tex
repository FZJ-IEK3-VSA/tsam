% Architecture and workflow of ETHOS.TSAM — the manuscript's Fig. 1.
%
% ── NOTATION: UML 2.5.1 ───────────────────────────────────────────────────
%   * Component and its nested internal structure: clause 11, Structured
%     Classifiers. Pipeline is drawn as a WHITEBOX. That is also arc42 §5
%     Level 2 (the whitebox/blackbox recursion), not a deviation from it.
%   * Dependency (dashed line, open arrowhead): clause 7, Common Structure.
%   * Action (ROUND-CORNERED rectangle): clause 16, Actions.
%   * ObjectFlow (solid line, open arrowhead): clause 15, Activities.
%   * Activity name in the upper left of the region that frames it: clause 15.
%
% ── FONT SIZES ARE SET HERE, NOT INHERITED FROM THE CLASS ─────────────────
% Reader request: 11 pt for the figure's ordinary type and 8 pt for the
% smallest. Both are met.
%
% The thing that makes that hard is that the printed size of a glyph is NOT
% the source size: the figure is placed at the full text width (165.1 mm)
% whatever its own width, so what reaches the page is
%
%       printed pt = source pt x 165.1 / (drawing width in mm)
%
% Scaling the whole drawing up therefore buys NOTHING — the fonts and the
% millimetres grow together and the quotient is unchanged. Type can only get
% bigger RELATIVE TO THE DRAWING, which means it is paid for out of the
% layout.
%
%              class 10pt      here        printed (x 165.1/162.1)
%   \small       9 pt        11 pt        11.22 pt
%   \scriptsize  7 pt         9 pt         9.18 pt
%   \tiny        5 pt         8 pt         8.16 pt
%
% ── WHAT THE PHASE ROW COST, AND WHY FIVE STRINGS ARE BROKEN ──────────────
% \tiny is the size that carries the stage names inside the four phase boxes,
% and the phase row is where the whole figure's width is decided. The row has
% 144 mm to spend (x 11..155, inside a 148 mm Pipeline whitebox) on
%
%       4 boxes + 3 gaps,
%
% the boxes sized by their longest stage name and the gaps by the widest line
% of the object-flow label that sits in them. At \tiny = 8 pt, taking every
% string as it stood, that is
%
%       4 x (26.89 + 3)  +  3 x (15.13 + 0.5)   =  166.5 mm     -> 22.5 over
%        `unstack_to_periods'    `Assignment'
%
% and there is no 22.5 mm to be had: the drawing is 162.1 mm against a ~165 mm
% budget, and every other row is already sized to its contents. So five strings
% are broken instead, each at a natural point, which brings the row to
%
%       4 x (22 + 3)  +  3 x (12.84 + 0.5 + 1.33)  =  144 mm    -> exact
%        `extreme_periods'       `Represen-'
%
% Four are stage names, and all four break at an UNDERSCORE with the underscore
% LEADING the continuation line, which is how the feature model already breaks
% `use_duration' / `_curves'. That is what keeps a wrapped name readable as one
% token — see UNDERSCORES AND MONOSPACE.
%
%   * `unstack_to_periods' -> `unstack_to' / `_periods'    26.89 mm
%   * `count_occurrences'  -> `count' / `_occurrences'     24.50 mm
%   * `add_period_sums'    -> `add_period' / `_sums'       23.57 mm  (italic)
%   * `accuracy_metrics'   -> `accuracy' / `_metrics'      23.09 mm
%   * `Assignment'         -> `Assign-' / `ment'           15.13 mm
%
% The last is the only NEW hyphen in the figure — `Representatives' was already
% hyphenated — and it is what lets the gaps come down from 15.63 to 14.67 mm,
% which is 4 mm of phase box.
%
% Breaking the four stage names costs NO height: Phase 3 was already the
% tallest at eight lines, and Phase 1 joins it there rather than passing it.
%
% Everything else fits whole, with the binding items at:
%       extreme_periods   21.52 mm  in 22 mm     (italic, the optional form)
%       assign_clusters   19.90 mm  in 22 mm     (roman)
%       Prepare data      21.40 mm  in 22 mm     (\scriptsize bold, the header)
% Those three are what stop \tiny going past 8 pt. A 9 pt \tiny needs 24.2 mm
% of text width, hence 27.2 mm boxes, hence a 153 mm phase row inside a 157 mm
% Pipeline — 9 mm more drawing than the page will take, which would scale the
% type back down further than the extra point raised it.
%
% ── WHERE THE HEIGHT CAME FROM ────────────────────────────────────────────
% The phase boxes went 24 -> 31.5 mm (Phase 3 now runs to eight lines) and the
% Pipeline whitebox 41 -> 48 mm, and yet the drawing grew only 4.9 mm, to
% 162.1 x 199.2 mm, aspect 1.229. Every box in the figure is sized to its
% contents plus a stated padding, so the 7 mm came back out of:
%   row A's top edge (-16 -> -14) and its three boxes, each now as tall as its
%   own member list; the row A -> Pipeline gap (12 -> 8 mm); row C and the
%   Configuration compartment; the externals stack; and the legend's row
%   pitch. None of it is arbitrary — see HOW THE BOXES ARE SIZED.
%
% ── WHY THE PHASES ARE ROUND-CORNERED AND THE COMPONENTS ARE NOT ──────────
% The four phases are not components. They are the temporal steps of one run,
% and an earlier revision drew them as sharp-cornered boxes with the same
% border as Tools/API/Results, which said the opposite: that the pipeline is
% built out of four more parts of the same kind as the boxes above it.
%
% UML already separates structure from behaviour by SHAPE, so no invention is
% needed. A Classifier is a sharp-cornered rectangle; an Action is a
% round-cornered one (clause 16). Making the phases round-cornered is therefore
% the whole fix, and it costs nothing else: colour keeps its one job (blue =
% tsam, grey = outside it) and shape alone carries structure-versus-behaviour.
% It also survives a greyscale print, which a colour difference would not —
% which is the whole reason the two-colour palette below is affordable.
%
% Two consequences follow, and both make the figure MORE conformant than the
% revision before it:
%
%   * The chain between the phases is an ObjectFlow — an activity edge, solid
%     with an open arrowhead (clause 15) — and its labels name the object that
%     flows. The previous revision had to draw it as a Connector between
%     nested parts (clause 11.4) and lean on §11.7 to let that Connector
%     realize an InformationFlow, purely to win a solid line that a dashed
%     Dependency could not be told apart from. That liberty is gone: an
%     ObjectFlow between Actions is solid because UML says it is.
%   * The Pipeline's second compartment is the behaviour it owns, so it carries
%     the activity's name in its upper left, \guillemotleft activity\guillemotright{} run\_pipeline
%     (src/tsam/pipeline/orchestrator.py:697). That is where UML puts an
%     Activity's name, and it tells the reader in one line that what follows is
%     a run, not a parts list.
%
% ── WHY CONFIGURATION AND COMMONS HAVE NO ARROWS ──────────────────────────
% Both are used by EVERY building block. An earlier revision drew one arrow
% into each (Pipeline -> Configuration, Algorithms -> Commons), which is worse
% than drawing none: it asserts a specific dependency that is not the real
% relationship, and a reader is entitled to conclude that nothing else uses
% them. UML has no "used by everything" edge, so the conformant device is a
% KEYWORD on the component: both carry \guillemotleft shared\guillemotright, both arrows are gone, and
% the legend says what the keyword means.
%
% Fill colour keeps its existing job (blue tint = exposes public API, white =
% internal, grey tint = external), so the two channels do not collide:
% Configuration stays blue because ClusterConfig and friends are public,
% Commons stays white.
%
% Each keyword is declared ONCE. \guillemotleft use\guillemotright and \guillemotleft shared\guillemotright live in the legend;
% \guillemotleft activity\guillemotright appears once in the drawing, on the compartment it names,
% because that is the position that carries its meaning.
%
% ── PALETTE: TWO COLOURS, SHARED WITH THE FEATURE MODEL ───────────────────
% Jülich blue and one grey, plus a tint of each, all of it declared once in
% palette.tex and \input by both manuscript figures. See that file for the
% reviewer request behind it and for the rule it imposes: anything the figure
% needs to distinguish beyond blue-versus-grey is carried by shape, line style
% or typography. Concretely:
%   * the phase fill is white — the round corners already say "action";
%   * the object flows are blue at 0.6 mm, twice the dependency's weight, and
%     solid-versus-dashed does the telling apart;
%   * optional stages are grey ITALIC (see below).
%
% ── OPTIONAL STAGES ───────────────────────────────────────────────────────
% Stages that run only when the caller configures them are set in GREY ITALIC
% inside the phase boxes. Italic, not a hue, is what carries the meaning: the
% "Phase n" tag on the first line of every box is grey too, so grey alone
% would be ambiguous, and italic is the one channel left that costs no colour
% and no space. The legend swatch is the word "italic" set exactly the way an
% optional stage line is set. Verified against
% src/tsam/pipeline/orchestrator.py:
%   Phase 1  prepare_data          normalize, unstack_to_periods,
%                                  [weights], [period sums]
%   Phase 2  cluster_candidates    assign clusters, representations
%   Phase 3  refine_representatives [extremes], [unweight], count occurrences,
%                                  [rescale], [segment]
%   Phase 4  build_result          denormalize, reconstruct + accuracy
% Note `unweight` is conditional — orchestrator.py:514 guards it on
% `prepared.weight_vector is not None` — and `count occurrences` (line 519) is
% the only unconditional step in Phase 3. An earlier draft of this figure
% called the whole of Phase 3 optional, which was wrong.
%
% ── TOP-ALIGNED PHASE TEXT ────────────────────────────────────────────────
% Reviewer request: "the text boxes in the pipeline box: I would align them at
% the top so that all box content starts at the same height and the headers in
% the respective box 1-4 are in one line."
%
% They were not, and the reason is structural rather than a slip. The four
% boxes are one row and share one `minimum height`, but they hold seven, four,
% eight and five content lines (tag + header + stages). A TikZ node centres
% its text vertically inside its minimum height and offers no `align=top`, so
% each header sat at its own height.
%
% The fix is one node per phase for the BOX and a second, `anchor=north`, for
% the TEXT, placed at a fixed -65.5 for all four. The boxes keep their common
% height and their common top edge at -64; only the slack moves, to the bottom
% of the shorter boxes, where it reads as the row being one block.
%
% ── HOW THE BOXES ARE SIZED ───────────────────────────────────────────────
% Every box is its content plus a stated padding, not a round number. That is
% where the type's extra size came from, so any box that is edited has to be
% RE-MEASURED rather than nudged. The paddings are:
%
%   row A / row C boxes   members start 1 mm below the compartment rule and
%                         the box ends 1.5-1.9 mm below the last line
%   phase boxes           text anchored 1.5 mm below the top edge, 1.64 mm of
%                         box below the tallest phase (3)
%   external boxes        content centred, box height rounded up to the mm
%
% The phase row is centred on -79.75, which is also the height at which the
% object flows run. Keeping the CENTRE fixed rather than the top edge is what
% lets the box height change without moving the flows or their labels.
%
% ── PRINT TARGET ──────────────────────────────────────────────────────────
% US Letter, 1 inch margins, text column 165.1 x 228.6 mm, every figure placed
% at full text width (wp:extent cx="5943600" EMU = 6.5 in).
%   * ASPECT h/w <= 1.24, or the scaled figure leaves no room for a caption.
%   * WIDTH <= ~165 mm, or Word scales the drawing DOWN and every font with it.
% The drawing measures 162.1 x 199.2 mm, aspect 1.229 — 1.8 mm of height to
% spare, and 3 mm of width that is deliberately NOT spent (spending it would
% shrink the type, see FONT SIZES). The aspect is what breaks first now.
%
% ── LAYOUT GRID (millimetres, y negative downwards) ───────────────────────
%   columns  c1 = 27.25 (9..45.5)   c2 = 76 (51..101)   c3 = 132.5 (108..157)
%     Column widths follow their longest member line at \scriptsize = 9 pt:
%     32.55 mm in c1, 45.79 in c2, 44.78 in c3. The member lists indent with
%     \hspace{2mm} rather than \quad, which at 9 pt is 3.17 mm — the 1.2 mm
%     that buys the 7 mm c2/c3 gap the Algorithms -> Pyomo lane needs.
%   row A    top edge -14 for all three; heights are per-box
%            Tools   -14..-35.5   (3 member lines, 10.75 mm)
%            API     -14..-43     (5 member lines, 18.51 mm)
%            Results -14..-39.5   (4 member lines, 14.63 mm)
%            header centred at -18.3, compartment rule -22, members from -23
%   Pipeline y -51..-99    whitebox, x 9..157; header -55.3, rule -59
%     the activity name sits in the compartment's upper left at (11,-59.5),
%     anchored north west; it is \tiny, 2.65 mm tall, so it clears the phase
%     tops at -64 by 1.85 mm.
%     four parts 25 mm wide with 14.67 mm gaps, spanning 11..155,
%     y -64..-95.5:
%       11..36        (c  23.50)     50.67..75.67  (c  63.17)
%       90.33..115.33 (c 102.83)    130..155       (c 142.50)
%     2 mm of pipeline box is left either side of the row.
%     phase TEXT is a separate node anchored north at y -65.5. Phases 1 and 3
%     are the tallest at eight content lines, 28.36 mm, so they end at -93.86
%     with 1.64 mm of the box to spare.
%     object flows run at y -79.75 across the gaps; their labels are
%     free-standing nodes anchored south at y -74.75, each inside its own
%     14.67 mm gap. The widest label line is "Represen-" at 12.84 mm, and the
%     nodes carry NO `text width` — every break is by hand — so the widest node
%     is 13.34 mm and clears the phase boxes by 0.665 mm a side. The 5 mm from
%     the flow to the label is set by the ARROWHEAD, not the line: a Straight
%     Barb at scale 2 on a 0.6 mm line reaches ~1.7 mm above it, and at the
%     previous 3 mm a descender came within ~1.3 mm of the barb and read as
%     touching it.
%     They are NOT `pos=` labels: pos on a multi-segment path applies to the
%     last segment only, and a white-filled label centred on the flow would
%     leave only a stub of visible line at each end.
%   row C    top edge -106   Commons/Algorithms -106..-120 (one line of text)
%            Configuration -106..-137.5 (header pair + 5 member lines)
%   externals c1 Plotly -144..-153 and pandas/NumPy -154..-164.5;
%             c2 scikit-learn -148.25..-160.25, c3 Pyomo -147.5..-161.
%             All four are centred on -154.25, which is what makes the row
%             read as one row.
%   legend rows y -169, -177, -185; row 2 has THREE columns (swatch at x 8,
%     dependency arrow 55..67, object flow arrow 100..112), which is what lets
%     the shape swatch in without a fourth row. The longest legend run,
%     "object flow between phases", ends at 151.83 — outside the c3 column but
%     inside the package boundary at 160.5, so it does not set the width.
%   Lanes, each checked against every other line sharing it:
%     x = 150   Pipeline -> Results        (y -51 .. -39.5)
%     x = 104.5 Algorithms -> Pyomo        (y -113 .. -154.25); clear of
%               Configuration, which starts at x 108
%     x =  76   API -> Pipeline (-43..-51), Pipeline -> Algorithms (-99..-106),
%               Algorithms -> scikit-learn (-120..-148.25); disjoint y-ranges
%     x =   1   Tools -> Plotly, outside the package boundary at 5.5
%   The "exact kmedoids" label hangs off the RIGHT side of the x = 104.5 lane,
%   anchored west at (106,-144.3), so it touches the edge it names and only
%   that one. It sits 3.3 mm below the package boundary at -141 and 3.2 mm
%   above the Pyomo box at -147.5.
%
% ── TRAPS RE-CHECKED HERE (see the project notes) ─────────────────────────
%   * A TikZ node CLIPS NOTHING: an over-long line spills across its border and
%     silently sets the drawing's width. Every node below has a `text width`.
%   * `inner sep=0` on any full-width text block.
%   * Guillemets as \guillemotleft / \guillemotright — literal UTF-8 renders as
%     "nsharedz" under T1. \textperiodcentered{} for the middot, --- for the
%     em dash.
%   * A TikZ STYLE cannot be applied to part of a node's text; the phase tags
%     and the two kinds of stage line use \newcommand DECLARATIONS instead.
%   * A node's text is ALWAYS vertically centred in its `minimum height`;
%     there is no `align=top`. Top-aligning content inside a fixed-height box
%     takes a second node — see TOP-ALIGNED PHASE TEXT.
%   * ITALIC IS NOT ROMAN. The optional stage lines are italic and measure
%     ~2 % NARROWER than the roman form; measuring `add period sums` in roman
%     (21.61 mm) and fitting it to a 22 mm box would have been luck, not
%     design. Both forms are listed below.
%   * MEASURE text, do not estimate it. `_measure.tex` is the harness: it
%     \settowidth's a string at a given size and TYPESETS the result, because
%     tectonic swallows \typeout. Widths that bind this layout:
%
%     \tiny = 8 pt, stage names, against the phase boxes' 22 mm text width.
%     Every one is snake_case, so these are the UNDERSCORED forms — an
%     underscore is wider than the space it replaced (`accuracy_metrics' is
%     1.24 mm wider than `accuracy metrics'), which is what pushed three of
%     them over the box and made them break.
%         \texttt{unstack_to_periods}  26.89   BROKEN -> 14.94 / 11.95
%                                              (\texttt is monospace at
%                                               1.494 mm/char, so 10 + 8)
%         count_occurrences            24.50   BROKEN -> 7.22 / 17.28
%         add_period_sums              23.57 i BROKEN -> 14.77 / 8.79
%         accuracy_metrics             23.09   BROKEN -> 11.37 / 11.72
%         extreme_periods              21.52 i <- binds the box
%         assign_clusters              19.90      representations 19.71
%         apply_weights                18.59 i
%         denormalize                  15.60      reconstruct     14.63
%         normalize                    12.62      unweight        11.57 i
%         segment                      10.41 i    rescale          8.68 i
%         Phase 1 (tag)                10.18      i = italic (optional stage)
%     \tiny = 8 pt, elsewhere
%         \guillemotleft activity\guillemotright{} \texttt{run_pipeline}  32.11   ends at x 43.1
%         .representation takes        27.01   Config, tw 45 with a 2 mm indent
%         HiGHS ... CPLEX              48.16   Pyomo, tw 45 -> wraps to 2 lines
%     \tiny = 8 pt, object-flow labels, against a 14.17 mm node budget
%         Assignment    15.13  BROKEN -> Assign- 9.57 / ment 6.56
%         Represen-     12.84  <- binds the gap        tatives 8.65
%         Prepared      11.83      Refined 9.83   Cluster 9.48   Data 6.43
%     \scriptsize = 9 pt
%         extremes: ExtremeConfig, ...)   43.79 + 2 mm indent = 45.79  c2, tw 46
%         + aggregate(data, n_clusters,   42.59                        c2, tw 46
%         + Distribution, MinMaxMean      42.78 + 2 mm indent = 44.78  c3, tw 45
%         + unstack_to_periods            32.55                        c1, tw 33.5
%         + ConcurrencyMetrics            32.19
%         Prepare data (phase header)     21.40   bold, in the 22 mm phase box
%         stage runs only when configured 45.84   legend row 3, ends 60.84
%         object flow between phases      38.33   legend row 2, ends 151.83
%         exact kmedoids                  21.87   edge label
%     \small = 11 pt
%         pandas \textperiodcentered{} NumPy  29.72   external, tw 33.5
%         Configuration                       22.71   c3 header
%
%   * The legend swatch takes `rounded corners=1.5mm`, not the phases' 2.2 mm.
%     A 2.2 mm radius on a 6 mm-tall swatch eats three quarters of its height
%     and reads as a lozenge rather than as the same shape, smaller.
%
% ── UNDERSCORES AND MONOSPACE ─────────────────────────────────────────────
% Two separate conventions, and they used to be confused with each other.
%
% THE UNDERSCORE says which words are one stage. Every stage name in the phase
% boxes is one snake_case token — `assign_clusters`, `add_period_sums`,
% `count_occurrences` — because a space could not carry that once the row's
% width forced the longest of them onto two lines: `count' above `occurrences'
% read as two stages, not one. An underscore leading the continuation line
% (`count' / `_occurrences') keeps a wrapped name legible as a single token.
% This is the whole of what the underscore claims; it does not claim that the
% string is copy-pasteable.
%
% MONOSPACE says the string is the LITERAL identifier, spelled as the code
% spells it. Only two qualify: `unstack_to_periods`, which is in tsam.__all__,
% and the activity's own name `run_pipeline`. The rest are shortened stage
% names, not exported symbols — the code calls them `_apply_weights_df`,
% `add_period_sum_features`, `_count_occurrences`, `rescale_representatives`
% and `segment_typical_periods` (orchestrator.py), every one of which is
% 19-23 characters and would need a 29-34 mm box at \tiny = 8 pt against the
% 22 mm the row can afford. Setting shortened names in monospace would promise
% a literalness they do not have, so they stay in the text face.
%
% This is also what makes them fit: monospace is 1.494 mm/char at 8 pt, half
% again as wide as the text face for these strings.
%
