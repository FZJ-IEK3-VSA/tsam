# tsam benchmarks

Time **and** peak-memory benchmarks for `tsam.aggregate`, built on
[`pytest-benchmark`](https://pytest-benchmark.readthedocs.io/) +
[`pytest-benchmem`](https://github.com/fluxopt/pytest-benchmem) (memray-backed
memory in the same run). `pytest-benchmem` requires Linux or macOS.

Two suites:

| File | What it varies | What it holds fixed |
|------|----------------|---------------------|
| `bench_scaling.py` | `timesteps` × `columns` × `timesteps_per_period` × `clusters` × `method` | — |
| `bench_features.py` | one feature axis at a time (representation/concurrency, extremes, segmentation, toggles) | data size (`8760 × 12`, daily periods, `clusters=8`) |

`bench_scaling.py` is one parametrized `test_scale` whose **dimensions are native
pytest params**, so you select any slice from the CLI with `-k`:

```bash
# everything (the full cross-product; slow — usually you slice instead)
pytest benchmarks/bench_scaling.py --benchmark-only --benchmark-save=headline

# just the timesteps-sweep (hierarchical, fixed columns/period/clusters)
pytest benchmarks/bench_scaling.py \
    -k "hierarchical and columns_4 and timesteps_per_period_24 and clusters_8"

# compare all methods at one size point
pytest benchmarks/bench_scaling.py \
    -k "timesteps_8760 and columns_4 and timesteps_per_period_24 and clusters_8"
```

`timesteps_per_period` is realised as `period_duration` hours at the data's native
1h resolution, so `periods == timesteps // timesteps_per_period`. Every run records
all five dimensions plus derived `periods` / `feature_width` in `extra_info`, so
plots can use any of them as an axis. Data is generated by tiling the real
`docs/notebooks/testdata.csv` (seeded, deterministic).

Levels live in `_data.py` (`TIMESTEPS`, `COLUMNS`, `TIMESTEPS_PER_PERIOD`,
`CLUSTERS`, `METHODS`) — edit there to extend the space.

> **`-k` caveat:** matching is by substring, so `-k columns_4` also matches
> `columns_48`. Add `and not columns_48` for an exact slice. (The figure scripts
> don't rely on `-k` — they filter the tidy DataFrame by column.)

### Timeouts for slow methods

`kmedoids` (exact MILP) and `kmaxoids` can explode at scale, so each such case is
first probed in a subprocess with a hard 20 s timeout (`_timeout.py`). A case that
overruns is **skipped** (dropped → gap in the figures), and once a method times
out at some size, its larger sizes are skipped too.

## Install

```bash
uv pip install -e ".[develop]"   # includes pytest-benchmem[plot]
```

## Time + memory

```bash
pytest benchmarks/ --benchmark-only --benchmark-memory \
    --benchmark-columns=min,median,mean --benchmark-save=headline
```

Saved runs land in `.benchmarks/<platform>/<NNNN>_<label>.json`.

## Docs figures

The [Performance & Scaling](../docs/background/performance.md) page is generated
from one saved run. The script reads it into a tidy DataFrame via
`pytest_benchmem.load_long_df` (no manual JSON parsing) and filters by dimension:

```bash
pytest benchmarks/ --benchmark-only --benchmark-save=headline   # ~8 min
python benchmarks/make_docs_figures.py                          # the method-scaling figure
```

## Regression check & plots (`benchmem`)

```bash
# Diff a run vs the best/baseline and fail on a regression threshold
benchmem compare .benchmarks/**/<run>.json --fail-on 1.10   # >10% slower/heavier -> exit 1

# Scaling curves — dims come from the params; pick the metric with --columns
benchmem plot .benchmarks/**/<run>.json --columns peak      # peak memory
benchmem plot .benchmarks/**/<run>.json --columns median    # time

# Benchmark across installed/tagged versions in one shot
benchmem sweep tsam v4.0.0 HEAD --suite benchmarks/
```

There is no committed baseline or CI gate — save a run per revision and
`benchmem compare` locally when touching a hot path. Extra knobs when needed:
`--benchmark-memory-profile DIR` (dump memray profiles) and
`@pytest.mark.benchmem(isolate=True)` (process-level RSS for the heaviest cases).

## Notes

- The largest corner (`timesteps=262800`, 30 years) drives hierarchical
  clustering to ~11k periods → `O(periods²)` distance matrix; expect it to be slow
  and memory-heavy. Trim `TIMESTEPS` in `_data.py` if that's too much.
- `kmedoids` is an exact MILP and is capped to `2016` rows in the feature suite.
- `benchmark_tuning.py` is a separate standalone script for the tuning API.
