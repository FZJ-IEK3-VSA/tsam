# tsam benchmarks

Time **and** peak-memory benchmarks for `tsam.aggregate`, built on
[`pytest-benchmark`](https://pytest-benchmark.readthedocs.io/) +
[`pytest-benchmem`](https://github.com/fluxopt/pytest-benchmem) (memray-backed
memory in the same run). `pytest-benchmem` requires Linux or macOS.

`bench_scaling.py` holds a fixed **1-year** horizon and varies the levers a user
actually dials — as native pytest dimensions, so any slice is one `-k` away:

| dimension | ids | levels (`_data.py`) |
|-----------|-----|----------------------|
| `resolution_min` | `res_60min` … | `RESOLUTIONS_MIN` = 1h / 15min / 5min |
| `period_hours`   | `period_24h`, `period_168h` | `PERIOD_HOURS` = daily / weekly |
| `columns`        | `columns_4` …    | `COLUMNS` |
| `clusters`       | `clusters_12`    | `CLUSTERS` |
| `method`         | method name      | `METHODS` |

Resolution drives both the timestep count and the timesteps-per-period, so the
period count stays realistic (≈365 daily, ≈52 weekly) instead of exploding. Data
is generated by tiling the real `docs/notebooks/testdata.csv` (seeded,
deterministic). `test_representation` sweeps the representation methods, all
clustered with hierarchical.

```bash
# a single method's resolution sweep, daily, at the base width
pytest benchmarks/bench_scaling.py -k "hierarchical and period_24h and columns_4"

# all methods at one size point
pytest benchmarks/bench_scaling.py -k "res_60min and period_24h and columns_4"
```

> `-k` matches by substring, so `columns_4` also matches nothing else here, but
> `res_5min` would also need care around future levels. The figure scripts filter
> the tidy DataFrame by column instead of relying on `-k`.

## Staying fast & bounded

Each case is measured **once** (`rounds=1`) — we want the scaling shape, not
statistical rigor. Every case is bounded *before* it runs, so there is no runtime
timeout machinery:

- `MAX_INPUT_CELLS` skips the `timesteps × columns` corners that would OOM.
- The explosion-prone `kmedoids` (exact MILP) and `kmaxoids` run only where they
  stay tractable — at the base column width, and (for `kmedoids`) only on small
  period counts: every weekly point, but daily only at hourly resolution. See
  `bench_scaling._slow_feasible`. Skipped cases just show as gaps in the figures.

## Install & run

```bash
uv pip install -e ".[develop]"                                 # incl. pytest-benchmem[plot]
pytest benchmarks/ --benchmark-only --benchmark-save=headline  # a few minutes
python benchmarks/make_docs_figures.py                         # renders both figures
```

Saved runs land in `.benchmarks/<platform>/<NNNN>_<label>.json`. The
[Performance & Scaling](../docs/background/performance.md) page is built from one
such run; `make_docs_figures.py` reads it via `pytest_benchmem.load_long_df`.

## Regression check & plots (`benchmem`)

```bash
benchmem compare .benchmarks/**/<run>.json --fail-on 1.10   # >10% slower/heavier -> exit 1
benchmem plot .benchmarks/**/<run>.json --columns peak      # peak memory
benchmem plot .benchmarks/**/<run>.json --columns median    # time
```

There is no committed baseline or CI gate — save a run per revision and
`benchmem compare` locally when touching a hot path.

`benchmark_tuning.py` is a separate standalone script for the tuning API.
